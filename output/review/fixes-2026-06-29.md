# SupoClip — Remediation Plan

**Date:** 2026-06-29
**Companion to:** `output/review/audit-2026-06-29.md`
**Scope:** This is a plan only. No code was changed (per `qa.md`). Per the project's "never defer" principle, **every** issue found in the audit is listed here regardless of severity — none are dropped.
**Format:** Issues are prioritized Critical → High → Medium → Low. Each carries: problem, root cause, remediation steps, effort, and dependencies. Effort scale: **S** ≈ <1h, **M** ≈ 1–4h, **L** ≈ 1–2 days. Items are framed to fit the project's VUW workflow (one file/error per unit, pre/post git checkpoint, `./checkpython.sh` green before close).

> **Sequencing thesis:** Fix the gate and the integration test FIRST (C-4, C-5), and **couple them** — the gate must *run* the real-output test, not just coverage/lint. Without that pairing, every other fix is unverifiable in the way that lets these bugs ship. Then fix the user-facing wiring (C-1, C-2), then clean the migration debt (C-3), then work down High→Low.
>
> **The bar for "done" — read this against the git history.** The 304-commit log shows these exact defects have been "fixed" repeatedly across two migrations and still regressed: **subtitle/caption/sync churned across 47 commits** (sync alone 29 — incl. "add diagnostic logging for caption sync debugging"), dead-code cleanup run in multiple phases (DEAD-001..010), and repeated coverage/quality-gate campaigns (GATE-001, TEST-001..011, INT-001..004) — yet this audit found subtitles *still* unwired, the 37 MB `frontend/` *still* present, and `checkpython.sh` *still* phantom. **A fix applied for the Nth time is not done when it works once; it is done only when a test makes the regression impossible.** Therefore: **C-1, C-2, and C-5 are closed ONLY on integration-level verification — a real produced artifact or a served HTTP route — never on a per-file `./checkpython.sh` green.** Per-file VUW granularity (103 VUW commits, 56 checkpoints in the history) structurally cannot see the *seam between files*, which is exactly where every headline bug (C-1, C-2, O7, O9) lives. That is why the prior fixes didn't stick.

## CRITICAL — app is non-functional for its core purpose

### C-1 — Subtitles & all style customization never reach generated clips
- **Problem:** Every UI-produced clip has no burned-in captions, font, or styling. The Settings page is dead end-to-end.
- **Evidence:** `home.py:91-97` builds `ProcessingRequest` with no `subtitle_style`; `video_service.py:384-392` passes `subtitle_style=None` into `ClipOptions`; `clip.py:310` gates *all* subtitle work behind `if opts.subtitle_style is not None`. `UserPreferences` is referenced only in `settings.py`/`models.py`.
- **Root cause:** Wiring gap — Settings→pipeline seam was never connected; unit tests *codify* the None default as correct (`test_clip.py:342`, `test_video_service.py:138-140`).
- **Remediation:**
  1. In `home.py render()`, call `load_prefs()` and construct a `SubtitleStyle` from `UserPreferences` (font family/size/color/stroke/shadow/position).
  2. Pass it (plus `logo_path`, `custom_prompt`) into `ProcessingRequest`.
  3. Verify it flows `home → process_video → ClipOptions → write_ass_file → ffmpeg ass= filter`.
  4. **Replace** the tests that assert `subtitle_style is None` is correct with tests asserting a real style reaches `write_ass_file` (depends C-5).
- **Effort:** M. **Depends on:** C-5 (to verify real output), H-7 indirectly.

### C-2 — Clip playback & download return HTTP 404
- **Problem:** `main.py` never mounts the clips directory; the task page serves `/clips/{filename}`. Users can never view or download output.
- **Evidence:** no `app.add_media_files`/`add_static_files` in `main.py:_startup`; consumers at `task.py:79,106`. CLAUDE.md: "Clips served via FastAPI static files at `/clips/{filename}`."
- **Root cause:** Wiring gap; no test exercises the HTTP route (all mocked).
- **Remediation:** In `_startup()` add `app.add_media_files('/clips/', Path(get_config().temp_dir) / 'clips')`; also call `get_config().ensure_temp_dirs()`. Add a route smoke test (depends C-5).
- **Effort:** S. **Depends on:** none to fix; C-5 to verify.

### C-3 — 37 MB dead `frontend/` directory (paper migration)
- **Problem:** React/Next.js + Prisma frontend the spec declares "deleted" was never removed: 37 MB, 123 git-tracked files, 32% (667/2056) of graphify nodes.
- **Evidence:** `spec.md:90` "deleted"; `frontend/` present (`next-env.d.ts`, `tsconfig.tsbuildinfo`, `src/generated/prisma/` incl. wasm + native `.node` binaries).
- **Root cause:** Migration documented complete, `git rm` never run.
- **Remediation:** `git rm -r frontend/`; `rm -rf frontend/`; add `frontend/` to `.gitignore`; run `graphify update .` to regenerate the (then-clean) graph.
- **Effort:** S. **Depends on:** none. (Coordinate with H-11 debt cleanup.)

### C-4 — Phantom quality gate `checkpython.sh`
- **Problem:** Cited as the MANDATORY pre-commit gate by spec.md, CLAUDE.md, AGENTS.md, qa.md, rules-python.md — exists in neither the tree nor git history. No end-to-end correctness has ever been enforced.
- **Root cause:** Documentation describes a gate that was never authored.
- **Remediation:** Create `checkpython.sh` running the union of documented tools, failing non-zero on any error: `ruff check src tests` + `ruff format --check` + `mypy src` + `pyright src` + `bandit -r src` + `radon cc src -n C` (fail on any C) + `xenon --max-absolute B src` + `deptry .` + `grimp` import check + `pytest --cov=src --cov-branch --cov-fail-under=100 tests/`. **The pytest invocation MUST include the C-5 real-output integration tests** (do not gate them out / mark `slow`-skip in CI) — a gate that runs only coverage + lint passes GREEN on the current non-functional app (coverage is already 100%), which is the precise false-confidence mechanism that produced this audit. Make it executable; wire into a corrected `.pre-commit-config.yaml` (H-11) and CI.
- **Effort:** M. **Depends on:** **C-5 (the gate is meaningless without a real-output test to run — couple them)**; M-1 (branch coverage will surface new gaps — stage threshold); C-3/H-11 (so the gate runs clean).

### C-5 — No real-output integration test (the test that would have caught C-1, C-2, O3–O13)
- **Problem:** The suite never produces or inspects a real `.mp4`/`.ass`/HTML page; the entire output-correctness bug class is invisible.
- **Evidence:** `test_pipeline_e2e.py:70-98` mocks `_generate_clips_concurrently`; `tests/fixtures/sample_video.mp4` (real 5,441-byte MP4) used by zero tests.

That suite did not stick **because it was mocked** — it never produced or inspected a real artifact. C-5 must NOT be another mocked suite; it must produce real files and assert against them, or it becomes the 48th failed sync fix.

  1. Add `tests/integration/test_pipeline_real_output.py`: run the real `transcribe → analyze(mock LLM only) → clip` path on `sample_video.mp4`, calling **actual ffmpeg**; assert the output `.mp4` exists, is non-zero, and `ffprobe`-checks dimensions (9:16) + codec (H.264/AAC).

  3. Add a browser smoke test (NiceGUI `TestClient` or `claude-in-chrome`) for the served `/clips/` route (asserts HTTP 200, not 404) and the phone-frame preview.
  4. Mark ffmpeg-dependent tests so they skip cleanly where ffmpeg is absent locally — but they **must run in CI and in `checkpython.sh` (C-4)**, never permanently skipped.
- **Effort:** L. **Depends on:** none (enables verification of nearly everything else; C-4 depends on this).

## Subtitle Correctness Playbook (the 47-commit problem)

Subtitles/captions/sync churned across **47 commits** and still don't render. This section is the **single concrete map** from "broken" to "working properly," because the scattered items (C-1, H-1, H-4, C-5) individually don't tell a dev the whole path — and the #1 historical trap is **re-fixing sync logic that the redesign already solved**.

### What is ALREADY correct (verified 2026-06-29 — do NOT re-fix this)

The 29 sync commits fought the *old* MoviePy/Playwright renderer. The NiceGUI/ASS redesign solved sync **structurally**, and the live code is correct:

- **Timestamp units are consistent end-to-end.** `_tokens_from_result` emits `start`/`end` in **seconds** (internal only) → `merge_bpe_tokens` converts to `start_ms`/`end_ms` (`transcribe.py:76-77`) → `transcribe_video` returns ms → `video_service` passes ms → `filter_words_for_segment` expects ms (`clip.py:143`) → `generate_ass_subtitles` reads `start_ms`/`end_ms`. No units mismatch in the live path.
- **Re-basing is correct.** `filter_words_for_segment` (`clip.py:143-156`) subtracts the segment start offset, so a word at 25.4 s in a clip starting at 25 s becomes `start_ms=400`. The ffmpeg command uses `-ss` **before** `-i` (`clip.py:222-223`), which re-bases output PTS to 0 — so ASS timings (relative to 0) align to the trimmed clip. **This is the exact thing SYNC-001 was trying to fix in the old arch; the new arch gets it right by construction.**
- **Word selection rule** (midpoint-in-range, `clip.py:151`), **per-word ASS events, position** (75% via `calculate_margin_v`), and **hex→ASS-BGR color** are all correct.

**Implication:** the path to working subtitles is SHORT — the machinery works; it is simply never invoked because the style is `None`. Resist the historical reflex to "fix sync."

## HIGH

### H-1 — ffmpeg filter-path injection / no escaping
- **Problem:** `ass={ass_path}:fontsdir={fonts_dir}` interpolated raw into `-vf`; any space/colon/comma in `TEMP_DIR` breaks the filtergraph silently. Spec 10.4 requires escaping.
- **Evidence:** `clip.py:212-215`. Tests use clean `/tmp/`.
- **Remediation:** Escape `\`, `:`, `'` per libass rules (or pass paths via `filename=` with quoting). Add a test with a path containing spaces/colons.
- **Effort:** S. **Depends on:** C-5.

### H-2 — BGR frame passed to RGB-expecting MediaPipe
- **Problem:** Degraded face detection → faces missed → silent center-crop.
- **Evidence:** `face_detect.py:62` — no `cv2.cvtColor(frame, COLOR_BGR2RGB)` before `detector.process()`; docstrings confirm BGR in.
- **Remediation:** Convert BGR→RGB before `process()`. Add guard `if results is None or not results.detections`.
- **Effort:** S. **Depends on:** C-5 (to verify on real frames).

### H-3 — cv2-absent fallback returns hardcoded (1920,1080) → wrong crop
- **Problem:** Portrait source cropped as landscape with no error; cv2 is an undeclared transitive dep.
- **Evidence:** `clip.py:392-396`, `face_detect.py:170-174`.
- **Remediation:** Replace cv2 dimension probe with `ffprobe` (already required by the ffmpeg-only mandate) and **fail loudly** on probe failure instead of guessing. Either declare `opencv-contrib-python` as a direct dep with rationale, or remove cv2 frame extraction in favor of ffmpeg `select` (spec 4.14).
- **Effort:** M. **Depends on:** C-5.

### H-4 — Karaoke / context-line subtitles unimplemented
- **Problem:** Core differentiator (spec 9.2: active word primary + dimmed context words via ASS inline tags) absent; code emits one bare word per event.
- **Evidence:** `subtitles.py:125-188`; `SubtitleStyle` missing `secondary_color`/`shadow_color`/`bold`.
- **Remediation:** Group phrase windows (≤6 words), emit one event per active word with `{\c…}` inline overrides dimming neighbors; add the missing style fields and set `shadowcolor`/`bold` in `_build_style`. (FOSS-1.)
- **Effort:** L. **Depends on:** C-1 (style must reach the clip), C-5.

### H-5 — `custom_prompt` dropped from the LLM user prompt
- **Problem:** Custom AI instructions silently weakened/ignored, especially on local LLMs.
- **Evidence:** `analyze.py:542` passes `custom_prompt` to `build_system_prompt` only, not `_build_user_prompt`.
- **Remediation:** Forward `custom_prompt` to `_build_user_prompt`. Add a test asserting it appears in the user turn.
- **Effort:** S. **Depends on:** none.

### H-6 — LLM timestamps not bounds-checked vs video duration
- **Problem:** Hallucinated `start=300` on a 150s video passes validation → blank/0-byte clip from ffmpeg seek past EOF.
- **Evidence:** `validate_segments` checks duration only, not bounds.
- **Remediation:** Pass `duration_s` into `validate_segments`; reject/clamp segments exceeding it.
- **Effort:** S. **Depends on:** none.

### H-7 — `error_message` never written → broken error banner
- **Problem:** Error banner always shows generic "unknown error"; a reloaded failed task shows no error at all.
- **Evidence:** `video_service.py:123-124` writes `progress_message` instead of `task.error_message` (`models.py:72`); read at `task.py:157,251`.
- **Remediation:** Write the error to `task.error_message` (keep `progress_message` for live status). Add a test asserting `error_message` is set on failure.
- **Effort:** S. **Depends on:** none.

### H-8 — stdlib `logging` instead of mandated `structlog`
- **Problem:** Inconsistent logging; loses structured context.
- **Evidence:** `video_service.py:14,35`, `analyze.py:27`, `download.py:18`.
- **Remediation:** Replace with `structlog.get_logger(__name__)`; convert `%s` calls to key=value. One VUW per file.
- **Effort:** S–M. **Depends on:** none.

### H-9 — `Config()` bypasses `get_config()` singleton (×4)
- **Problem:** Re-parses `.env` on every pipeline call; defeats test patching; violates SPOT.
- **Evidence:** `analyze.py:364,428,538`, `video_service.py:302`.
- **Remediation:** Replace all with `get_config()`.
- **Effort:** S. **Depends on:** none.

### H-10 — Unbounded clip concurrency (no `MAX_WORKERS`)
- **Problem:** `TaskGroup` spawns ALL clips' ffmpeg processes simultaneously — resource exhaustion risk on long videos.
- **Evidence:** `video_service.py:252-254`; `MAX_WORKERS` config absent.
- **Remediation:** Add `MAX_WORKERS` (default 2) to `config.py`; bound concurrency with an `asyncio.Semaphore` inside the TaskGroup.
- **Effort:** M. **Depends on:** M-7 (config var).

### H-11 — Stale migration artifacts (pre-commit, AGENTS.md, dead test script)
- **Problem:** `.pre-commit-config.yaml` hooks all scoped to nonexistent `^backend/` (every hook a no-op); `AGENTS.md` documents the deleted monorepo; `tests/verify_subtitle_renderer.py` imports deleted `src.subtitle_renderer.BrowserSubtitleRenderer`.
- **Remediation:** Rescope pre-commit hooks to `^(src|tests)/` and wire `checkpython.sh`; rewrite `AGENTS.md` for the single-Python app; `git rm tests/verify_subtitle_renderer.py tests/output/logo_test.mp4`.
- **Effort:** M. **Depends on:** C-4 (gate to reference).

### H-12 — Upload path & non-YouTube URL handling broken
- **Problem:** Uploads written to hardcoded `/tmp` (`home.py:150`) → rule violation + mid-pipeline `FileNotFoundError`; non-YouTube URL stored `source_type="upload"` (`home.py:219`) → treated as local path → `FileNotFoundError`.
- **Remediation:** Write uploads to `get_config().temp_dir / "uploads"` (ensure dir exists). Introduce/route a `"url"` source type for non-YouTube yt-dlp URLs and handle it in `video_service`.
- **Effort:** M. **Depends on:** M-8 (`ensure_temp_dirs` call).

### H-13 — Missing retry, exception class, and `src/exceptions.py`
- **Problem:** No `@stamina.retry` on the LLM call (spec 11.5; `download.py` has it); generic `AnalysisError` instead of `InsufficientSegmentsError`; no centralized `src/exceptions.py` (`SupoClipError` base).
- **Remediation:** Create `src/exceptions.py` with `SupoClipError` + the documented subclasses; have modules inherit from it; add `@stamina.retry(on=Exception, attempts=3, wait_initial=2.0, wait_max=10.0)` to the analyze call; raise `InsufficientSegmentsError` when <1 valid segment.
- **Effort:** M. **Depends on:** none.
