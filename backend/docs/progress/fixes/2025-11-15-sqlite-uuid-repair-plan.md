# SQLite UUID Auto-Generation Repair Plan
Date: 2025-11-15

## Executive Summary

**Issue:** SQLite DEFAULT clause for UUID generation (`DEFAULT (lower(hex(randomblob(16))))`) is NOT being respected when using raw SQL via SQLAlchemy's `text()` wrapper. This causes NOT NULL constraint failures when inserting records.

**Root Cause:** SQLite's DEFAULT clause works for direct SQL but NOT through SQLAlchemy's `text()` wrapper with parameterized queries. The DEFAULT is only applied when the column is completely omitted from the INSERT statement, but SQLAlchemy's execution layer doesn't recognize this.

**Impact:**
- Tasks table: INSERT fails completely (blocking video processing)
- Generated_clips table: INSERT will fail (blocking clip creation)
- Sources table: WORKS because it uses SQLAlchemy ORM, not raw SQL

**Solution:** Explicitly generate UUIDs in Python code before INSERT statements for all raw SQL operations.

### 2. Why source_repository.py Works

**source_repository.py create_source() (lines 14-36):**
```python
@staticmethod
async def create_source(
    db: AsyncSession,
    source_type: str,
    title: str,
    url: Optional[str] = None,
    metadata: Optional[Dict[str, Any]] = None
) -> str:
    """Create a new source record and return its ID."""
    from ..models import Source

    source = Source()  # ✅ Uses ORM model
    source.type = source_type
    source.title = title
    source.url = url
    source.metadata = metadata

    db.add(source)  # ✅ SQLAlchemy manages UUID generation
    await db.flush()

    source_id = source.id  # ✅ ID is already generated by model default
    logger.info(f"Created source {source_id}: {title} ({source_type})")
    return source_id
```

**Key Difference:** Uses SQLAlchemy ORM (`Source()` model instantiation), which applies Python-side defaults from `models.py` (the `generate_uuid_string` function).

## Appendix A: Technical Deep Dive

### Why SQLite DEFAULT Doesn't Work with SQLAlchemy text()

**SQLite Behavior:**
- DEFAULT clause is evaluated ONLY when column is completely omitted from INSERT
- When column appears in INSERT (even with NULL), DEFAULT is NOT used
- SQLAlchemy's parameterized queries always include all columns

**Example:**
```sql
-- This works (DEFAULT is used):
INSERT INTO tasks (user_id, status) VALUES ('user1', 'pending');

-- This fails (DEFAULT is NOT used, id=NULL violates NOT NULL):
INSERT INTO tasks (id, user_id, status) VALUES (NULL, 'user1', 'pending');

-- SQLAlchemy text() generates the second form when id is in the query
```

**PostgreSQL vs SQLite:**
- PostgreSQL: Has native UUID type and gen_random_uuid() function
- SQLite: No UUID type, uses TEXT with hex(randomblob(16))
- PostgreSQL DEFAULT works more reliably with ORMs
- SQLite requires explicit value generation

### Why SQLAlchemy ORM Works

**ORM Execution Flow:**
1. Create model instance: `source = Source()`
2. Python-side default applied: `id = generate_uuid_string()`
3. ORM builds INSERT with generated id value
4. Database receives INSERT with valid UUID already in place

**Raw SQL Execution Flow:**
1. Developer writes SQL: `INSERT INTO tasks (...) VALUES (...)`
2. SQLAlchemy wraps with text() and parameterizes
3. No Python-side defaults applied (model not involved)
4. Database receives INSERT without id value
5. SQLite looks for DEFAULT clause... but column was in INSERT, so DEFAULT not used
6. NULL value violates NOT NULL constraint → ERROR

- Triggers don't work well with RETURNING clause

### Alternative 4: Remove NOT NULL Constraint

**Idea:** Make id column nullable, generate UUID after INSERT

**Why Not:**
- Primary key MUST be NOT NULL (SQL standard)
- Would break referential integrity
- Creates data integrity issues
- Not a valid solution

## Summary

This repair plan provides a systematic approach to fixing UUID auto-generation in SQLite when using raw SQL via SQLAlchemy's `text()` wrapper. The issue is caused by SQLite's DEFAULT clause not being respected in parameterized queries, requiring explicit UUID generation in Python code.

The fix is straightforward:
1. Import `uuid` module
2. Generate UUID before INSERT: `record_id = str(uuid.uuid4())`
3. Include `id` in INSERT column list and VALUES clause
4. Add `"id": record_id` to parameters

This pattern must be applied to both `task_repository.py` and `clip_repository.py`, while `source_repository.py` already works correctly because it uses SQLAlchemy ORM.

All fixes are organized into Verifiable Units of Work (VUWs) with mandatory verification checklists, ensuring each fix is tested and validated before proceeding to the next.
