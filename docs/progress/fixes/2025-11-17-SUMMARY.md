## Issues Identified

### Issue 1: Incorrect Clip Duration
**Problem:** Clips are 7-8 seconds instead of 10-45 seconds
**Evidence:** Log shows all 6 clips range from 6.80s to 12.56s, with average 8.49s
**Root Cause:** Validation threshold is 5 seconds, but AI prompt says 10 seconds
**Fix:** Change validation from `if duration < 5:` to `if duration < 10:`
**Location:** `backend/src/ai_structured.py` line 274
**Risk:** LOW (single line change, well-tested)
**Impact:** HIGH (all future clips will be correct duration)

### Issue 2: Broken Captions
**Problem:** Subtitles show fragmented words like "EK WE CONTINU" instead of "WE CAN CONTINUE"
**Evidence:** Cache file contains broken BPE tokens: "Y", "es", "U" instead of "Yes", "Uh"
**Root Cause:** Old cached transcripts bypass the word reconstruction feature because cache is loaded before reconstruction can run
**Fix:** Implement cache versioning to invalidate old caches and force re-transcription with reconstruction
**Location:** `backend/src/transcription_mlx.py` lines 69-78 and 96-101
**Risk:** MEDIUM (requires cache deletion, but improves quality significantly)
**Impact:** CRITICAL (affects all cached videos, severely impacts user experience)

## Root Causes Confirmed

### Issue 1: Validation-Prompt Mismatch

**The Problem:**
1. System prompt tells Groq LLM: "MINIMUM 10 seconds, DO NOT return shorter clips"
2. But validation code only rejects: `if duration < 5`
3. So Groq learns: "I can return 5-9 second segments and they'll pass validation"
4. Result: Groq optimizes for "complete thoughts" in 6-8 second window

**Why Validation Wins Over Prompt:**
- AI sees validation accepting 5+ second clips
- AI response happens first, validation happens after
- No hard constraint during generation, only after
- Validation is the actual enforcement mechanism

### Issue 2: Cache Bypass Prevents Feature from Running

**The Problem:**
1. Word reconstruction feature added (commit 4ab6105)
2. Cached transcripts exist from before feature
3. Cache check happens BEFORE reconstruction code
4. Old cache has `get("words")` with broken BPE tokens
5. Function returns early, reconstruction never runs

**The Timeline:**
- T1: Video 1 transcribed → BPE tokens cached (before 4ab6105)
- T2: Word reconstruction feature added (commit 4ab6105)
- T3: Video 1 processed again → old cache loaded → reconstruction skipped
- Result: Captions still have broken tokens

## Recommended Fixes

### Fix 1: Align Validation with Prompt (1 line change)

**File:** `backend/src/ai_structured.py` line 274

**Change:**
```python
# FROM:
if duration < 5:

# TO:
if duration < 10:  # Match system prompt requirement
```

**Why This Works:**
- AI will know that only 10+ second clips pass validation
- Groq will optimize for 10-45 second segments
- Validation and prompt are now aligned

**Validation:**
- Run tests: `pytest tests/test_clip_duration*.py`
- Check logs for: `ACCEPTED: Segment ... (XX.XXs ...`
- All durations should be >= 10s

---

### Fix 2: Invalidate Old Caches via Versioning (20 lines)

**File:** `backend/src/transcription_mlx.py`

**Changes:**
1. Add version constant: `TRANSCRIPT_CACHE_VERSION = "v2"`
2. Check version when loading cache
3. Add `cache_version` field to cached data
4. Reject mismatched versions (triggers re-transcription)

**Why This Works:**
- Old caches don't have `cache_version` field
- Code detects mismatch and re-transcribes
- New transcription includes word reconstruction
- Captions show complete words

**Validation:**
- Delete old caches: `find temp -name "*.transcript_cache.json" -delete`
- Process video
- Check logs for: `✅ Word reconstruction complete`
- View clip captions - should show "Yes", "Well", not "Y", "es"
