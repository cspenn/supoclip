## ISSUE 2: CAPTION CLIPPING - COMPREHENSIVE ANALYSIS

### What Fixes Were Previously Attempted

#### Fix 1: MoviePy 2.x API Migration (CRITICAL)
**Source**: `docs/progress/fixes/2025-11-19-caption-moviepy-margin-fix.md`

MoviePy 2.x changed the `.margin()` API:
- **Old (broken)**: `text_clip.margin(bottom=3, ...)`
- **New (fixed)**: `text_clip.with_effects([Margin(bottom=3, ...)])`

**Error before fix**: `'TextClip' object has no attribute 'margin'`
**Impact**: 100% caption failure - 0 subtitles created

#### Fix 2: Increased Margin (from 3px to 12px)
**Source**: `docs/progress/fixes/2025-11-19-caption-clipping-fix-verification.md`

The root cause identified:
- Original intent (commit e9ace2c): 10px bottom margin
- Actual implementation: 3px bottom margin (discrepancy)
- Font descender depth: 5-10px depending on font size
- Total required: 8-13px minimum

**Fix**: Increased margin to 12px

```python
# Before
text_clip = text_clip.with_effects([Margin(bottom=3, top=3, left=2, right=2, opacity=0)])

# After
text_clip = text_clip.with_effects([Margin(bottom=12, top=5, left=3, right=3, opacity=0)])
```

#### Fix 3: Dynamic Margin Based on Font Size (CURRENT)
**Source**: `docs/progress/fixes/2025-11-19-final-verification-report.md`
**Commit**: `c8a093b - fix(captions): implement dynamic margin to prevent descender clipping`

```python
bottom_margin = max(5, int(current_font_size * 0.35))
```

Margin scaling:
- 16px font: 5px margin
- 24px font: 8px margin
- 30px font: 10px margin
- 40px font: 14px margin

### Current Code Implementation Verification

### Potential Remaining Issues (from docs/progress/fixes/2025-11-19-root-causes.md)

1. **MoviePy TextClip Bounding Box Excludes Descenders** (60-75% confidence)
   - MoviePy may calculate text height from baseline to ascender top
   - Margin applied to incorrect bounding box
   - Actual rendered text extends below reported bounds

2. **Margin Applied Before Stroke** (40-50% confidence)
   - 1px stroke might extend beyond margin
   - Less likely since dynamic margin should accommodate this

3. **CompositeVideoClip Crops TextClip Edges** (30% confidence)
   - Text might be positioned such that bottom edge gets cropped

**Documented Investigation Results**:
- Test Coverage: 60+ test images across 5 test suites
- Reported as "9/9 tests passed" but user may still see issues
- The fundamental MoviePy bounding box behavior may need different approach

## ISSUE 3: TRANSCRIPT/CAPTION SYNC - ANALYSIS

### Known Timing Architecture

**Source**: `.serena/memories/video_pipeline_complete_analysis.md`

The pipeline has intentional precision loss at the AI formatting stage:

```
1. Transcription (parakeet-mlx): 1ms precision
2. Cache storage: milliseconds (int)
3. AI Formatting: LOSES precision -> MM:SS (1-second resolution)
4. AI Analysis: MM:SS -> MM:SS (1-second boundaries)
5. Clip Creation: Float seconds (regains precision for video cut)
6. Subtitle Filtering: Millisecond precision (from cache)
```

**Key Code Locations**:
- `backend/src/video_utils.py:826-850` - `parse_timestamp_to_seconds()`
- `backend/src/video_utils.py:862-887` - `SubtitleWordFilter.get_relevant_words()`
- `backend/src/transcription_mlx.py:250-252` - Word timing extraction

### Potential Sync Issues

**From Memory Analysis**:

1. **Floating-Point Precision Loss** (MEDIUM-HIGH probability)
   - AI receives MM:SS with 1-second quantization
   - Example: 1234ms -> "00:01" -> 1.0s (233ms lost)
   - Impact: Up to 1 second error in clip boundaries

2. **Word Boundary Mismatch** (MEDIUM probability)
   - If clip boundary falls in middle of a word
   - Subtitle timing errors occur
   - Words at clip edges may be incorrectly filtered

3. **Cache Staleness** (LOW-MEDIUM probability)
   - Word reconstruction enabled by default
   - Old caches (v1) have different word timings than v2
   - Cache version check exists but user-specific caches might persist

### Subtitle Word Extraction Flow

**From `backend/src/video_utils.py` (lines 1056-1061)**:
```python
# Convert clip timing to milliseconds and get relevant words
clip_start_ms = int(clip_start * 1000)
clip_end_ms = int(clip_end * 1000)
relevant_words = SubtitleWordFilter.get_relevant_words(
    transcript_data, clip_start_ms, clip_end_ms
)
```

The subtitle filtering correctly:
1. Converts clip times to milliseconds
2. Extracts words overlapping the clip timerange
3. Converts to relative timing (offset from clip start)

**Current Word-by-Word Implementation** (lines 994-1028):
- Creates one TextClip per word
- Uses exact word timing from transcript cache
- Skips words < 50ms duration

## Recommendations

### For Logo Rendering Issues
1. **Verify logo path resolution**: Check if relative paths are being resolved correctly in production
2. **Add logging**: Ensure `"Added logo overlay at {position}"` message appears in production logs
3. **Test all service paths**: Verify logo works through `/start`, `/start-with-progress`, and job queue paths

### For Caption Clipping Issues
1. **Increase margin further**: Try 20-25px if 14px (40px font) still clips
2. **Alternative approaches**:
   - Use PIL/Pillow to render text with known bounds
   - Manually calculate text bounds including descenders
   - Position text higher in frame
3. **Font-specific testing**: Test with fonts that have larger descenders

### For Transcript/Caption Sync Issues
1. **Consider preserving millisecond precision**: Pass MM:SS.mmm format to AI
2. **Add boundary padding**: When extracting clips, add small buffer to start/end
3. **Word boundary awareness**: Ensure clip boundaries don't split words
