## SAFETY ISSUES

### Critical Security Concerns

1. **Path Traversal Risk (Medium Severity)**
   - **Location:** VUW 6, line 1218-1230
   - **Issue:** `get_font_file()` endpoint accepts font_name parameter and serves files
   - **Code:**
     ```python
     font_path = Path(font.file_path)
     if not font_path.exists():
         raise HTTPException(status_code=404, ...)
     return FileResponse(path=font_path, ...)
     ```
   - **Risk:** If file_path from database is manipulated, could serve arbitrary files
   - **Mitigation:** Add path validation to ensure file is within allowed directories

2. **SQL Injection via JSON Fields (Low Severity)**
   - **Location:** VUW 5, line 872
   - **Issue:** `metadata_json: Mapped[Optional[dict]] = mapped_column(JSON, nullable=True)`
   - **Risk:** SQLAlchemy handles this safely, but no explicit validation on JSON content
   - **Mitigation:** Add Pydantic validation before storing metadata

3. **Font File Hash Collision (Low Severity)**
   - **Location:** VUW 4, line 792
   - **Issue:** Uses only first 16 characters of SHA256: `return sha256_hash.hexdigest()[:16]`
   - **Risk:** Increases collision probability from negligible to very low
   - **Mitigation:** Use full hash (64 chars) or explain why 16 is sufficient

1. **Missing Permission Checks (Medium Severity)**

   - **Location:** VUW 5, init.sql proposal
   - **Claimed:** PostgreSQL syntax will work
   - **Reality:** Project uses SQLite (`sqlite+aiosqlite:///./supoclip.db`)
   - **Issues:**
     - `TIMESTAMP WITH TIME ZONE` → SQLite doesn't support (use `TIMESTAMP` or `TEXT`)
     - `uuid_generate_v4()::text` → PostgreSQL function (SQLite needs Python UUID)
     - `JSON` type → Works in SQLite 3.38+ but may need `TEXT` fallback
   - **Fix Required:** Rewrite schema for SQLite compatibility

3. **hashlib Listed as Dependency**
   - **Location:** VUW 1, line 178
   - **Claimed:** Need to add `hashlib` to dependencies
   - **Reality:** hashlib is Python built-in module since 2.5
   - **Impact:** Will cause uv sync error
   - **Fix Required:** Remove from dependencies list

### Moderate Accuracy Issues

4. **Prisma Schema Field Names Don't Match SQLAlchemy**
   - **Location:** VUW 5, line 922-940
   - **Issue:** Prisma uses `filePath` (camelCase) but SQLAlchemy uses `file_path` (snake_case)
   - **Code:**


   - **Fix Required:** Use `@@map("file_path")` in Prisma or ensure consistent naming

5. **Font Validation Logic May Be Too Strict**

   - **Impact:** May reject valid fonts (false negatives)

6. **Frontend Component Import Path May Conflict**

## EFFECTIVENESS CONCERNS

### Design Concerns

1. **Performance: Synchronous Font Detection**
   - **Location:** VUW 7, initialize() method
   - **Issue:**
     ```python
     async def initialize(self) -> None:
         bundled = await self.get_bundled_fonts()  # Blocks startup
         system = await self.detect_system_fonts()  # May take 5+ seconds
     ```
   - **Impact:** Application startup blocked until all fonts detected
   - **Better:** Background task after startup or lazy initialization

2. **Database: No Pagination for Large Result Sets**
   - **Location:** VUW 8, get_all_fonts()
   - **Issue:** Returns all fonts in single query (could be 1000+)
   - **Impact:** Memory and performance issues with large font collections
   - **Better:** Add offset/limit parameters for pagination

3. **Search: Inefficient String Matching**
   - **Location:** VUW 7, _fuzzy_filter_fonts()
   - **Code:**
     ```python
     if (query_lower in font.name.lower() or
         query_lower in font.family.lower()):
     ```
   - **Issue:** O(n*m) substring search on every query
   - **Impact:** Slow search with 500+ fonts
   - **Better:** Use database LIKE query or full-text search index

4. **API: No Rate Limiting**
   - **Location:** VUW 6, all endpoints
   - **Issue:** refresh_fonts endpoint could be abused
   - **Impact:** DoS potential via repeated refreshes
   - **Better:** Add rate limiting middleware

### Scalability Concerns

5. **Font File Serving: No CDN or Caching Headers**
   - **Location:** VUW 6, get_font_file()
   - **Code:** `headers={"Cache-Control": "public, max-age=86400"}`
   - **Partial:** Has cache header but:
     - No ETag support
     - No Content-Encoding (compression)
     - No range request support
   - **Better:** Add ETag based on file_hash

6. **Database: No Connection Pooling Optimization**
   - **Issue:** Each font service instance creates new db session
   - **Impact:** Connection overhead
   - **Better:** Reuse session or use connection pool

### Architectural Concerns

7. **Tight Coupling: FontService Depends on Database**
   - **Issue:** Can't use FontService without database (even for bundled fonts)
   - **Impact:** Harder to test, can't run offline
   - **Better:** Make database optional, fallback to file-only mode

8. **Global State: _font_service Module Variable**
   - **Location:** VUW 6, line 1007
   - **Code:** `_font_service: Optional[FontService] = None`
   - **Issue:** Global mutable state is anti-pattern
   - **Better:** Use dependency injection via FastAPI Depends()

9. **Missing Transaction Boundaries**
   - **Location:** VUW 7, cache_fonts()
   - **Issue:** Commits after each font insert in loop
   - **Better:** Single transaction for all inserts (batch commit)
